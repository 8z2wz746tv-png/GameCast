# 异地朋友测试清单

## 公网模式前提

1. 所有人只安装同一版本 GameCast，不需要安装 Tailscale、ZeroTier 或 WireGuard。
2. 控制节点的 `/health` 必须可从朋友电脑访问；邀请中的服务器地址必须是 HTTPS 公网地址。
3. 若使用 TURN，确认公网防火墙已放行 `3478/tcp`、`3478/udp` 和 relay UDP 端口范围。
4. 若使用 SFU，确认 LiveKit 的 WSS 地址、API 密钥和 UDP 媒体端口可访问。
5. 房主复制唯一的房间信息模板，朋友把整段内容粘贴到加入页的服务器地址框，客户端会自动填入口令和地址。

## 第一轮连接

1. 房主选择“互联网节点”并创建房间，先使用 `1080p60` 共享整个屏幕。
2. 第一名观看者加入并选择共享者，检查状态标识是否为 `P2P` 或 `TURN`。
3. 第二名观看者加入同一路共享，LiveKit 健康时应显示 `SFU`；没有配置 LiveKit 时仍可使用 P2P。
4. 核对观看端显示的实际分辨率、帧率、码率和音频状态，播放游戏声音确认连续有声。
5. 观看者切换到另一名共享者，再切回原共享者，旧画面和旧音频应立即停止。

## 故障恢复

1. 观看过程中临时断网 3 秒后恢复，客户端应自动重连；无法恢复时显示明确的控制节点或 ICE 错误。
2. P2P 失败且控制节点配置了 LiveKit 时，该观看关系应切换为 SFU；本次观看期间不会反复切回 P2P。
3. 最后一名 SFU 观看者离开后，共享者应取消 SFU 发布；只剩 P2P 观看时不应持续产生 SFU 流量。
4. 连续观看至少 2 小时，观察是否有周期性卡顿、画面定格或内存持续增长。
5. 无法恢复时，双方点击“导出诊断包”，并记录大致故障时间和状态标识。

## 带宽预期

- 1080p60 单观众上限约 12 Mbps，加上协议开销后建议共享者稳定上行不低于 15 Mbps。
- 第一名 P2P 观众会增加共享者一份上行副本；第二名起若 SFU 可用，共享者通常只需维持一条 SFU 上行。
- TURN relay 和 LiveKit 媒体会产生公网流量费用；P2P 成功时控制节点不承载视频。
